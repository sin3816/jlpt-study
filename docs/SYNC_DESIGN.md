# PC ↔ 폰 동기화 설계

## 1. 목표

| 목표 | 설명 |
|---|---|
| 자동 | 앱을 열거나 닫거나 공부하면 따로 누르지 않아도 맞춰진다 |
| 오프라인 우선 | 지하철처럼 인터넷이 없어도 공부는 그대로 된다. 연결되면 나중에 합쳐진다 |
| 기록 손실 없음 | 두 기기에서 같은 날 공부해도 어느 한쪽 기록이 덮어써지지 않는다 |
| 운영 부담 없음 | 서버를 만들거나 유지하지 않는다. 무료로 쓴다 |
| 개인 데이터 보호 | 토큰은 기기에만 저장한다. 저장소는 비공개로 둔다 |

## 2. 방식 비교와 선택

| 방식 | 자동 | 설정 난이도 | 비용·운영 | 판단 |
|---|---|---|---|---|
| 파일 내보내기·가져오기 (카톡·드라이브로 전달) | ✗ | 쉬움 | 없음 | **보조 수단**으로 유지. 가져오기도 병합으로 동작 |
| 같은 Wi-Fi에서 QR로 직접 전송 | ✗ (두 기기를 함께 켜야 함) | 보통 | 없음 | 회사 PC 방화벽 문제로 제외 |
| **GitHub 비공개 Gist** | ✓ | 토큰 1회 입력 | 무료, 서버 없음 | **채택**. 웹앱 호스팅(GitHub Pages)과 같은 계정 하나로 해결 |
| Supabase / Firebase | ✓ (실시간까지) | 프로젝트·테이블·보안 규칙·로그인 구현 | 무료 한도, 콘솔 관리 필요 | 여러 사람이 쓰게 될 때(3단계) 전환 |
| Google Drive API | ✓ | OAuth 클라이언트 등록·동의 화면 심사 | 무료 | 개인 앱에는 설정이 과함 |

**선택 이유:** 웹앱을 GitHub Pages에 올리므로 GitHub 계정은 어차피 필요합니다. Gist는 API로 읽고 쓸 수 있는 비공개 파일 저장소입니다. 토큰에 Gists 권한만 주면 다른 저장소에는 접근할 수 없습니다. 동기화 로직은 `SyncProvider`(pull/push) 경계 뒤에 있어서, 나중에 Supabase로 바꿔도 병합 코드는 그대로 씁니다.

## 3. 핵심 아이디어: 덮어쓰기가 아니라 병합

```
 PC(로컬 상태) ──┐                 ┌── 폰(로컬 상태)
                 ▼                 ▼
          pull → merge → push   pull → merge → push
                 └──► Gist(jlpt-sync.json) ◄──┘
```

- 동기화는 늘 **받기 → 합치기 → (달라졌으면) 올리기 → 로컬 반영** 순서입니다.
- `merge(A, B)`는 **교환·결합·멱등** 법칙을 만족합니다(단위 테스트로 보장).
- 그래서 순서가 꼬이거나 같은 동기화가 두 번 일어나도 결국 모든 기기가 같은 상태가 됩니다.
- 두 기기가 동시에 올려서 한쪽 업로드가 덮여도 손실되지 않습니다. 각 기기가 자기 기록을 로컬에 갖고 있다가 다음 동기화 때 다시 합치기 때문입니다.

## 4. 데이터 모델 (src/core/state.js, 스키마 v2)

모든 기록에 **ms 타임스탬프 `t`** 를 둡니다. 삭제는 지우지 않고 **삭제 표시(톰스톤)** 를 남깁니다.

| 필드 | 형태 | 병합 규칙 |
|---|---|---|
| `profile` | 학습 계획 1개 + `t` | 최근 것(t 큰 쪽)이 이김 |
| `compMeta` | `"날짜\|할일ID" → {on, t}` | 항목별 최근 것. 체크 해제도 기록되어 되살아나지 않음 |
| `completions` | 날짜 → 완료 ID 목록 | `compMeta`에서 **파생**(동기화 안 함) |
| `events` | `{id, date, title, t, deleted?}` | ID별 최근 것. 삭제는 `deleted:true` |
| `attempts` | 풀이 기록 `{id, …, t}` | ID 합집합(추가만 있음), 시간순, 최대 20,000건 |
| `wrong` | 문항 → 오답 상태 + `t` | 문항별 최근 것 |
| `cards` | 단어 → 간격 반복 상태 + `t` | 단어별 최근 복습 |
| `activity` | 날짜 → **기기ID** → `{q, cards, t}` | 기기별로 따로 셈. 합계는 화면에서 더함. 같은 날 두 기기 학습량이 모두 반영됨 |
| `mocks` | 모의고사 결과 `{id, …, t}` | ID 합집합 |
| `resetAt` | 전체 초기화 시각 | 최댓값. 이보다 오래된 기록은 모든 기기에서 버림 |
| `settings` | 테마·음성 속도 등 | **동기화 안 함**(기기마다 다를 수 있음) |
| `local` | 기기ID, 토큰, Gist ID | **동기화 안 함**, 내보내기에서도 토큰 제거 |

같은 `t`가 나오면 직렬화 문자열을 비교해 결정적으로 고릅니다.

**시계 차이 대비(하이브리드 논리 시계):** `App.now() = max(현재 시각, 마지막 값+1, 지금까지 본 가장 큰 t+1)`
- 폰 시계가 몇 분 늦어도, 다른 기기의 기록이나 초기화 시각을 한 번 받은 뒤에는 그보다 큰 `t`가 찍힙니다.
- 그래서 새 기록이 초기화에 지워지거나 LWW에서 지는 일이 없습니다.

v1(1.0.0) 데이터는 처음 열 때 자동 변환됩니다. 기존 기록은 `t=0`입니다. 레거시 ID와 학습량 키에는 그 기기의 ID를 넣어, 다른 기기의 v1 기록과 겹치지 않게 합니다.

### 충돌 예시

| 상황 | 결과 |
|---|---|
| PC에서 할 일 체크(10:00) → 폰에서 같은 할 일 해제(10:05) | 해제 유지 |
| 같은 날 PC 문제 10개, 폰 문제 5개 | 통계에 15개 |
| PC에서 일정 추가, 폰에서 그 일정 삭제 | 삭제 |
| 두 기기에서 계획을 각각 수정 | 나중에 저장한 계획 |
| 폰에서 같은 단어 카드를 나중에 복습 | 폰의 복습 간격 |
| 동기화 연결 상태에서 "모든 기록 초기화" | 양쪽 모두 초기화(확인 창에 안내) |
| 동기화 해제 상태에서 초기화 | 그 기기만 비움(`resetAt`을 남기지 않음) |
| 초기화 이후 데이터를 파일로 가져오기 | 이 기기의 이전 기록도 지워진다고 확인을 받은 뒤 합침 |

## 5. 전송 형식과 저장소

- 비공개 Gist 1개, 파일 `jlpt-sync.json`, 설명 `JLPT 스터디 동기화 데이터 (jlpt-study-sync)`
- `{ app:"jlpt-study", format:1, savedAt, savedBy, data:{…동기화 필드} }`
- 풀이 기록은 배열 `[id, qid, level, 섹션코드, chosen, correct, at, t]`로 압축합니다. 20,000건이어도 약 1.5MB입니다.
- API 응답이 1MB를 넘으면 내용이 잘립니다. 그때는 `raw_url`에서 원본을 받습니다.
- 두 번째 기기는 Gist ID를 몰라도 됩니다. 토큰만 넣으면 `GET /gists`에서 파일 이름으로 찾아냅니다.
  - 같은 파일이 든 Gist가 여럿이면 **가장 먼저 만든 것**을 골라 모든 기기가 같은 곳에 모입니다.
- 저장된 Gist가 404이면 먼저 계정에서 다시 찾고, 없을 때만 새로 만듭니다.

## 6. 언제 동기화하나 (src/renderer/sync.js)

| 계기 | 동작 |
|---|---|
| 앱 시작 | 받기·합치기 |
| 화면으로 돌아옴(폰에서 앱 전환 복귀) | 받기·합치기 |
| 앱을 벗어남(홈 버튼, 창 최소화) | 바로 올리기 |
| 학습 기록 변경 | 20초 동안 추가 변경이 없으면 올리기 |
| 화면이 켜져 있는 동안 | 5분마다 |
| 인터넷 다시 연결 | 즉시 |
| 설정 → 지금 동기화 | 수동 |

- 문제를 풀거나 단어 카드를 넘기는 중, 계획 수정 폼이나 입력 중인 글이 있을 때는 다른 기기 데이터가 들어와도 화면을 다시 그리지 않습니다. 기록은 같은 상태 객체에 이어서 쌓입니다.
- **업로드하는 동안 생긴 기록:** 업로드가 끝나면 지금 로컬 상태와 한 번 더 합칩니다(merge가 멱등이라 안전). 아직 안 올라간 변경이 남아 있으면(`dirty`) 곧바로 다시 동기화합니다.
- 동기화 도중에 또 요청이 오면 끝난 뒤 한 번 더 실행합니다.
- 모든 요청은 30초 제한 시간이 있어 멈춘 연결 때문에 동기화가 막히지 않습니다.
- 실패하면 오류를 설정 화면과 사이드바에 표시하고, 다음 계기에 다시 시도합니다.

## 7. 플랫폼별 통신

- **PC(Electron):** 렌더러는 `window.api.httpFetch`로 메인 프로세스에 요청합니다. 메인은 `net.fetch`(Chromium 네트워크, **Windows 프록시 설정을 따름**)로 보냅니다. 메인 프로세스는 요청을 다음처럼 제한합니다.
  - 허용 주소는 `api.github.com`과 `gist.githubusercontent.com`뿐입니다.
  - GET/POST/PATCH만 허용하고, 리다이렉트는 거부합니다.
  - 앱 화면(file://)이 보낸 요청만 받습니다.
  - 배포판은 테스트용 서버 지정(`JLPT_SYNC_API`)을 무시합니다.
- **폰(PWA):** 브라우저 `fetch`를 씁니다. CSP `connect-src`에는 위 두 주소만 허용합니다.

## 8. 보안

- 토큰은 **Fine-grained, Gists 읽기·쓰기만**, 만료 1년 이하를 권장합니다. 다른 저장소·계정 정보에는 접근할 수 없습니다.
- 토큰은 기기 로컬(PC: `%APPDATA%\jlpt-study\jlpt-data.json`, 폰: 브라우저 IndexedDB)에만 저장합니다. 입력칸은 가려서 표시합니다.
- Gist와 내보내기 파일에는 넣지 않습니다(테스트로 확인). 내보내기에서는 Gist ID 등 기기 전용 값(`local`)을 통째로 뺍니다.
- 연결을 해제하면 백업 파일까지 덮어써 토큰을 지웁니다.
- 향후: PC 토큰을 Electron `safeStorage`(Windows DPAPI)로 암호화합니다.
- 비공개(secret) Gist는 검색되지 않습니다. 다만 URL을 아는 사람은 볼 수 있습니다. 담기는 내용은 학습 기록뿐입니다.
- 폰을 잃어버렸으면 GitHub → Settings → Developer settings에서 토큰을 폐기하세요.
